## Shared root causes

### Clinical episode reference and projection

Scheduling paths treated a valid same-patient, same-institution episode
reference as sufficient reason to serialize clinical episode content. The
remediation separates linkage from reading:

- one fail-closed episode-reference resolver checks the complete operational
  ownership tuple;
- all scheduling responses use one narrow operational projection;
- clinical content remains available only through explicit clinical routes
  with medical-category and institution authorization.

### Security audit admission and lifecycle

Repeatable rejected requests did not share one explicit persistence policy,
and untrusted request identifiers reached a bounded database column. The
remediation adds:

- a static typed policy registry for repeatable security events;
- bounded, atomic counters with finite aggregation dimensions;
- retention eligibility for every bounded event;
- canonical request-ID normalization at ingress and audit persistence;
- a medical-category requirement for direct clinical access assertions before
  object resolution.

## Security invariants

1. Appointment creation authority does not grant clinical-read authority.
2. Patient and institution equality do not grant clinical-read authority.
3. Scheduling response shape is stable and independent of the caller role.
4. Invalid request metadata cannot suppress a required rejection audit.
5. Repeatable security failures have bounded persistence cost.
6. A non-medical actor cannot assert access to a clinical object.
7. Denied clinical assertions do not resolve the referenced object.

## Performance evidence

- a real PostgreSQL burst of 100 equivalent CSRF security events produced one
  actor-specific durable row with `occurrence_count=100`;
- a second actor produced a separate row;
- the measured test call for the 100-event parallel burst was 1.83 seconds,
  including application-level audit writes;
- expired bounded rows are removed in indexed batches of at most 100;
- operational appointment serializers no longer traverse or eager-load the
  `ClinicalEpisode` relationship. The response removes the entire nested
  episode object rather than conditionally hiding individual fields.

Payload byte size depends on synthetic names and episode content, so the
stable regression contract is structural: zero embedded episode fields and
zero episode PHI sentinels on every scheduling surface. Query behavior is
also structural: the required opaque-reference validation remains one tuple
lookup, while response serialization performs no episode relationship load.
